# Verify super threads

`scripts/self-hosted/super-thread-model/SuperThreads.tla` is a TLA+ model of super threads ([design](../../../docs/internals/super-threads.md)). A super thread S on environment E1 records every thread it launches (`t3_thread_launch` here or in a linked environment E2, and `create_threads`) in its append-only member list. Clients derive one sidebar section per super thread from that list and each thread's settled state. Settling the header plans, confirms, then settles the header and its unsettled members one by one. TLC checks every order of steps in a small world: S, a local child L (and L2, the new thread a retry starts after a crash), a remote child R on E2 (and R2, the new thread the agent's retry starts there after a crash), a `delegate_task` child D, an outside thread O, and a second super thread S2 on E2, with E1 crashes, launch retries, E2 outages, messages, auto-settle and hand settles.

## The rules

| Rule                          | In plain words                                                                                                                                                         | Harm when it breaks                                                                       |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `MembersOnlyOwnLaunches`      | Every member is a thread the super thread launched with `t3_thread_launch` or `create_threads`.                                                                        | A `delegate_task` child or an unrelated thread shows up in the group.                     |
| `AtMostOneGroup`              | No thread is a member of two super threads.                                                                                                                            | One thread appears in two sections.                                                       |
| `NoUnwarnedSettle`            | Settling the header never settles a busy member the confirmation did not list, or any thread (header included) that started new work after the confirmation was shown. | A member that just got new work is parked silently, and its open questions are dismissed. |
| `UnsettledMemberStaysVisible` | For a client that reaches both environments, an unsettled member is always a row of its shown section.                                                                 | A working or waiting member disappears from the sidebar.                                  |
| `EachThreadPlacedOnce`        | The client puts every thread it holds in exactly one place: a section header, a section row, the Settled shelf, or the ordinary sections.                              | Duplicate or missing rows.                                                                |
| `HeaderUnsettleKeepsMembers`  | Unsettling the super thread never changes a member.                                                                                                                    | Finished members come back with every new task.                                           |
| `EveryLaunchJoins`            | Once nothing is in flight, every thread S launched is a member, including one in E2 that E1 crashed before recording.                                                  | A launched thread is missing from its group and sits in the ordinary list.                |

The header is the thread the person acts on, with its status in view, so the confirmation lists only members (as the design says); `NoUnwarnedSettle` still covers the header for new work after the confirmation.

## Design choices the model requires

Each is a `CONSTANT`. `check.sh` turns each one off and confirms the rule it guards breaks.

| Choice                       | What the code must do                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Breaks without it                                                                                                                                                                                                    |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `WriteAheadLocal`            | A local launch records the member before it dispatches the launch (`recordLocalLaunch` before `ThreadMessageIntake.launchThread`; `recordLaunchedMember` before `thread.create` in `create_threads`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | `EveryLaunchJoins`: L is created, E1 crashes before the record, and the retry is a new thread L2, so L is never a member.                                                                                            |
| `LaunchOnlyMembership`       | Nothing but the super thread's own launch writes `super_thread.member.record`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | `MembersOnlyOwnLaunches`, `AtMostOneGroup`, `EachThreadPlacedOnce`                                                                                                                                                   |
| `ExcludeDelegates`           | `delegate_task`, local or remote (`RemoteDelegation` calls `t3_thread_launch` through forwarding directly), records nothing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | `MembersOnlyOwnLaunches`                                                                                                                                                                                             |
| `GuardSettleByRun`           | Each planned settle carries the latest run id the plan saw as `expectedLatestRunId`, and the server refuses it when a newer run exists.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | `NoUnwarnedSettle`                                                                                                                                                                                                   |
| `SectionFromAnyUnsettled`    | A section shows while the header or any held member is unsettled, not only while the header is.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | `UnsettledMemberStaysVisible` (the server auto-settles the idle super thread while L still works, and L vanishes)                                                                                                    |
| `SettledMembersLeaveSection` | A settled member is not a row; it sits on the Settled shelf.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | `EachThreadPlacedOnce`                                                                                                                                                                                               |
| `HeaderLeavesShelf`          | A settled super thread whose section shows is claimed as its header and left off the shelf.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | `EachThreadPlacedOnce`                                                                                                                                                                                               |
| `UnsettleHeaderOnly`         | Unsettling the super thread touches only the super thread.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | `HeaderUnsettleKeepsMembers`                                                                                                                                                                                         |
| `GuardEverySettle`           | Every settle the cascade sends is guarded: `planSuperThreadSettle` always plans the header, settled or not, and sends `expectedLatestRunId: null` for a thread with no run yet, which the `thread.settle` guard compares as `(latest?.id ?? null) !== expectedLatestRunId`. Web and mobile pass `null` through rather than dropping it.                                                                                                                                                                                                                                                                                                                                     | `NoUnwarnedSettle`: S launches L with no message, you press Settle, a message starts a run on L, you confirm, and an unguarded settle parks L while it works.                                                        |
| `ReplayRemoteLaunch`         | A super thread writes a launch bound for a linked environment down (`super_thread.launch.pending`) before it forwards it, and the record of the returned thread ends it in the same command. A failed call leaves it pending, since the thread may exist there anyway. After a restart, `replayPendingLaunches` (`apps/server/src/superThread/superThreadLaunches.ts`) sends each launch still pending again under the request namespace and `clientRequestId` it went out with, so E2 (which scopes the key by E1's peer session, persisted on both sides) answers with the thread it already made. A super thread's linked launch without a `clientRequestId` is refused. | `EveryLaunchJoins`: E2 creates R, E1 crashes before recording it, and the agent gives up; or retries, which after a restart is a new thread R2, because E1 scopes the forwarded key by the agent's provider session. |

## Open findings

A finding is a `finding-<name>.cfg` that `check.sh` expects to break its rule on the code as it is, listed in the findings section of `check.sh` with its candidate fix, if any. The design configs leave that rule out so the other rules still get a full check.

None open.

When a fix lands, set its constant in every config, put the rule back in the design configs, add a variant line for the constant, and delete the finding.

## Scope

- **Bounds:** `launch.cfg`: one E1 crash, one launch retry, one E2 outage, no messages or cascade. `settle.cfg`: two messages, one E2 outage, one settle cascade, launches without faults. `all-faults.cfg` (`deep`): every fault class at once. One super thread with its launches L, L2, R and R2 and a delegate D, plus S2.
- **Abstractions:** a run is `working`, `input` (approval or question) or `idle`. Settled is `settledOverride = "settled"`. Members are whole thread ids; each thread's environment is fixed.
- **Assumed:** the server serializes commands per thread; a `thread.settle` either commits or refuses as one step; the forwarded call returns the remote id only after E2 committed it (a call that fails may or may not have made the thread); a super thread's linked launch carries a `clientRequestId` (the server refuses one without); the super thread starts with its first message (draft send or the bridge's `task`). The model lets the cascade send its settles in any order, a superset of the code (header first, then members in parallel, members skipped if the header's settle fails).
- **Over-approximated:** auto-settle may settle any idle thread at any time (`ThreadSettlementService` is stricter: it refuses after an explicit unsettle and waits for inactivity).
- **Not covered:** archive, delete and snooze; more than one client; the sidebar's project filter and search; members of S2; S2 launching; the task map; the order of rows inside a section.

## When to run

Run it when a change touches:

- `apps/server/src/superThread/` (`recordLaunchedMember`, `applySuperThreadCommand`);
- `apps/server/src/mcp/toolkits/superThread/handlers.ts` (`recordLocalLaunch`, `recordForwardedLaunch`) and `apps/server/src/superThread/superThreadLaunches.ts` (`recordPendingLaunch`, `replayPendingLaunches`);
- `t3_thread_launch` in `apps/server/src/mcp/toolkits/project/handlers.ts` (the order of `recordLocalLaunch` and `ThreadMessageIntake.launchThread`, and the `recordForwardedLaunch` argument to `startsThreads`);
- `startsThreads`, `afterForwarding` or `routed` in `apps/server/src/mcp/McpToolAccess.ts` (the remote check runs before the call goes, with `environmentId`), or `scopedRequestId` in `apps/server/src/peer/PeerForwarding.ts`;
- `createThreads` in `apps/server/src/mcp/OrchestratorMcpService.ts` (the `recordLaunchedMember` call before `thread.create`);
- `apps/server/src/peer/RemoteDelegation.ts` (must keep calling forwarding directly, not through `routed`);
- the `thread.settle` guard or `dispatchMessage`'s auto-unsettle in `apps/server/src/orchestration-v2/Orchestrator.ts`, or `ThreadSettlementService.ts`;
- `packages/client-runtime/src/state/superThreads.ts` (`deriveSuperThreadSections`, `planSuperThreadSettle`);
- `apps/web/src/components/superThread/superThreadSettle.ts`, `settleThread` in `apps/web/src/hooks/useThreadActions.ts`, or the `superThreadSidebar` seam in `apps/web/src/components/Sidebar.tsx`;
- `apps/mobile/src/features/super-threads/useSuperThreadSettle.ts`, `settleThread` in `apps/mobile/src/features/home/useThreadListActions.ts`, or `apps/mobile/src/features/super-threads/superThreadList.ts`;
- the spec, its configs or `check.sh`.

## Run

```sh
scripts/self-hosted/super-thread-model/check.sh            # design configs, each choice turned off, open findings
scripts/self-hosted/super-thread-model/check.sh design     # design configs only
scripts/self-hosted/super-thread-model/check.sh variants   # choices turned off only
scripts/self-hosted/super-thread-model/check.sh findings   # open findings only
scripts/self-hosted/super-thread-model/check.sh deep       # all-faults.cfg: every fault class at once
```

It runs TLC from the repo flake's pinned nixpkgs (`nix shell --inputs-from . nixpkgs#tlaplus`), so nothing else needs installing. It prints one line per run and the directory holding the full TLC output, and exits non-zero on any unexpected result. The expected result is `ok` or `open` on every line.

On a 48-core machine the default run takes about 5 minutes: `launch.cfg` explores 1.7M distinct states, `settle.cfg` 96M. `deep` takes about 12 minutes (338M distinct states). Run the default on every relevant change, and `deep` before moving the sync commit.

## Read a result

Read every result with the `/statechart` skill: give it the spec and the failing config, cut down (fewer messages, no outage) when the config is too large for its single worker. It turns an invariant violation into the shortest path in plain words.

When a design config fails:

1. Retell the path in this repo's words: "S launches L with no message, you press Settle on the header, a message to L starts a run, you confirm, the client settles L".
2. Replay it against the code, one step per action, with the coverage table. A path the code cannot take means the model is wrong: fix the model and say what was wrong. A path the code can take is a finding: report it with the path, do not weaken a rule or flip a constant to make it pass, add a `finding-<name>.cfg`, and leave the rule out of the design configs it reaches.
3. A change that drops a design choice (for example, moving `recordLocalLaunch` after `launchThread`) shows up as that choice's variant: the design config with the constant set as the code now behaves fails the rule in the choices table. Set the constant to what the code does in the design configs and report the broken rule; do not ship the change.

When a variant line fails ("expected X to break, got pass"), the check has lost its power to catch that choice being dropped; find out why before trusting a pass. When a finding line fails, the code may have fixed it: confirm against the code, then follow **Open findings**.

## Change the verification

When a change is intended:

1. Update the actions in `SuperThreads.tla` that describe the changed code, and their rows in the coverage table.
2. Run `check.sh`. If a new design choice guards a rule, add a constant, set it in every config, and add a variant line in `check.sh`.
3. Run `check.sh deep`, then move the sync commit below forward. Move it only after confirming that every row of the coverage table describes the code at the new commit.
